# Voice polish and message actions

Implemented: compact voice bubbles use a sound-wave control and seconds, with click-to-play/pause, single-media playback, no native player or autoplay. The hold recorder shows a central overlay with actual RMS microphone samples, elapsed time and slide-to-cancel state. Audio analysis closes and disconnects when capture ends; unsupported analysis leaves neutral bars while recording remains usable.

Implemented: sender-only message options offer Recall for text/photo/video/voice/gift/system rows and Edit for text. Options have a visible ellipsis and long press; failed edit text survives retry. No recall/edit time limit. Recall overwrites content with Message recalled, removes image/video/audio references and increments a revision. Gift ledger transfers are unchanged. Editing validates trimmed 1–1000 characters and checks contact rules. Row locking and optimistic revisions reject competing edits; matching retries are idempotent. Cannot restore or edit a recalled message.

Security: public APIs are invoker wrappers over an explicitly authorized private-schema definer helper. Privilege is necessary to clear previously immutable media references. auth.uid must be the sender and a conversation participant; no caller-supplied owner. Client direct UPDATE is revoked, insert metadata forgery is rejected, and recipient receipts retain their existing narrow API. Notification previews for the same sender/conversation are sanitized after changes. Old media becomes unreferenced for existing owner cleanup. New signed URLs are unavailable to the recipient after recall; previously issued URLs may remain valid up to their existing five-minute expiry. Already downloaded/saved content cannot be erased from another device.

Sync: existing Realtime UPDATE plus 15-second foreground reconciliation changes only the edited/recalled bubble and leaves receipt-only/player updates in place. Opening chat now reads video/audio/action fields that the prior select omitted. Rendering ignores stale revisions. Notification and inbox access retain existing RLS; last-message recall previews use the tombstone.

Automated Verified: 242 checks including all message types, sender/recipient/outsider/no-auth authority, retry/stale/bounds, blocked edits versus recall, post-recall recipient media visibility, preserved read receipts, custom playback, real sample meter resource cleanup and in-place remote changes. Syntax/diff checks pass. Production migration metadata and before/after advisors separately checked at deployment. Not Verified: physical iPhone recording/meter, visual acceptance and real two-account synchronization.

Rollback: database/rollback-message-actions.sql disables future actions while preserving tombstones/protections. Recall intentionally clears original payloads and cannot restore them. Frontend changes can be reverted separately.
