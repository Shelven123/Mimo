# Local media upload checkpoint — 2026-10-11 Malaysia

Implemented: Host Plaza photos (six combined local/linked images), optional short Reel, local previews/removal and upload/preparation status; private-chat single photo via Plus → Send a photo with explicit send. Text-only legacy publish retained. Photos decode through the device canvas, flatten transparency, resize longest edge to 1600 and encode JPEG; original limit 20 MB / 50 megapixels, output 3 MB. HEIC depends on browser decoder support. MP4/MOV/WebM 30 MB, device metadata duration at most 90 seconds. No server transcoding or server duration guarantee.

Private `mimo-media` bucket permits only JPEG / MP4 / MOV / WebM, maximum object 30 MB. Canonical owner/post/message paths are validated before attachment. Storage writes use `upsert:false`; there is no UPDATE policy. Post image guards impose 3 MB, Reel 30 MB and matching MIME/extension with real object metadata. No foreign object reference, missing object, persisted token, alternative private-bucket URL, message identity mutation or forged Seen permitted. Existing RLS/contact rules still apply. Anonymous API execution denied; public API invoker with empty search_path. Helpers private and invoker.

Post files are readable to uploader or viewers of their actual visible post. Chat files are readable to uploader or actual message participants, only after send for recipient. Existing blocked-chat history remains readable; blocking prevents new upload/send. Signed URLs are bearer links valid for **300 seconds** even after auth/block changes. They are never persisted to message/post rows. Active pages renew every 120 seconds or on visibility; playing video source is not reset by renewal. Both video and cover sign independently. Logout/disposal suppresses late response display and clears private local previews/tokens.

Unchanged retry preserves request ID, prepared blobs and completed object paths. A lost upload response can return conflict on retry; server object existence/metadata/owner checks precede attachment. Changing draft begins a new request. Raw client metadata writes are not performed; files go through Storage SDK. Existing hosted HTTPS media remain supported.

Verified: 165 independent isolated PostgreSQL/DOM/media checks, changed JavaScript and inline-script syntax, whitespace. Tests simulate Storage SDK/camera DOM; they are not authenticated production uploads or a Safari visual test. Production migration metadata/no-UID read/advisors checked before frontend release. No actual customer message/post/report or financial record was created for verification.

Not Verified: real authenticated Storage upload/sign/download, Safari image orientation/HEIC decode, keyboard/album/gesture rendering, MOV/WebM codecs across devices, two-account transport, production concurrent publication/removal/retry. Security advisor retains prior findings described with remediation links in `NOTIFICATION_CENTER_REVIEW.md`; no new finding from this release.

Incomplete: resumable/background transfer, thumbnails when no cover supplied, server video duration/transcoding/moderation, storage quotas and orphan retention, private chat video/voice messages. Failed/discarded drafts may leave owner-only orphan objects. Client cleanup policy only permits unreferenced own paths; frontend deliberately does not auto-delete after ambiguous publish/send responses. Published references cannot be client-deleted. No claim that Storage allocation is unlimited or production moderation complete.

Rollback: revert frontend to previous checkpoint; `database/rollback-media-uploads.sql` stops new upload and image-send API without deleting files/rows/read policy. Keep reference guards and signed read support for already published media; do not expose bucket publicly or delete object metadata by SQL. Accepted call/Beauty unchanged.

Phone acceptance: Host choose 2 photos → publish → Photos view; choose <90 sec MP4 + cover → Reels; User browse; chat Plus → Send a photo → preview/cancel → explicitly Send; recipient view, inbox Photo and Seen; retry offline without changing draft; verify blocked send denied and third account cannot sign chat image.
