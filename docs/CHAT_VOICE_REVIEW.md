# Private chat voice messages

Entry: Chat → + → Voice message. Hold to record, release to send; slide up 64px or Cancel recording to discard. Keyboard/screen-reader activation starts recording; activate again to send. Close cancels recording and hides the panel. Failed sends retain playable audio, Retry send and Discard. Recording limit: 60 seconds and 5 MiB. No autoplay in received messages.

Recorder uses runtime MediaRecorder.isTypeSupported selection (audio/mp4 preferred, audio/webm fallback), microphone only, and canonical container MIME. See [MediaRecorder API](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder) and [MIME support check](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static). Permission denial/timeouts, release before permission completion, pointer/slide cancel, short capture, device error/background/logout/disposal are handled. Every accepted stream is stopped; late permission streams never start recording. Unsupported browsers fail visibly.

Database: CLI-created 20261011125546_mimo_chat_voice.sql applied via Supabase MCP. audio_url/audio_duration_ms; SECURITY INVOKER mimo_send_voice, empty search_path, authenticated-only execution. Existing conversation/contact/block/read-receipt RLS retained. Private m4a/voice.webm references require exact sender/chat/message identity and matching existing Storage metadata/MIME, up to 5 MiB. Stable request + duration must match on retry. Cleanup registration lock and permanent claim protection retained, including audio. Audio allowed only in chat paths; post formats remain unchanged. No customer messages/files created for production testing.

Verified: 228 automated checks. JS/inline syntax/diff checks pass. Live column/bucket/function metadata and no-UID media denial checked. Before/after advisors identical apart from observation timestamps; no new findings.
