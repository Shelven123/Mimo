# System Web Push

Implemented: Settings → Notifications has explicit Enable/Disable on this device. iPhone instructions require Safari → Share → Add to Home Screen, opening the Home Screen app and allowing the system prompt. Home/settings include a scoped manifest and PNG icons. Worker only handles push/click; it never caches or intercepts page/media fetches. Existing accepted call/Beauty code stays untouched.

Server: Supabase Edge mimo-push v1 implements custom authentication (verify_jwt=false is intentional). Config requires a verified Auth user and returns only the public VAPID key. Dispatch requires a 244-bit random backend secret held with the VAPID private key in Vault. Keys initialize lazily on first authenticated enable; no secret provisioning by the user, no secret in frontend/repository. Service-only RPCs read config/lease/finish jobs; public registration is invoker → narrow private definer with Auth UID/session validation, endpoint allowlist, bound ownership and ten-device cap. Raw subscription inserts/updates denied; clients read/delete only their own devices.

Push is separate from in-app read history. Notification INSERT queues eligible subscribed devices and immediately wakes the worker through asynchronous pg_net. A minute cron retries failures; jobs expire after five minutes, eight attempts, forty jobs per claim. Leases skip locked jobs. Actual encrypted Web Push request generation is pinned to web-push 3.6.7; redirects prohibited and outbound destinations limited to Apple/Google/Mozilla push services. Invalid/expired provider endpoints are removed. Retries are at least once; stable tags collapse repeated display, but provider acceptance followed by timeout can cause repeat alerts. No exact-once delivery guarantee.

Before dispatch, current preferences, read-state, blocks and the owning Auth session are checked again. Sessions disappearing cascade subscriptions/jobs, protecting shared-device logout and account changes even if local unsubscribe fails. Me/Settings logout attempts cleanup without delaying logout beyond five seconds. Push body is always generic; no chat/support/comment text, attachment URLs or private keys are sent in the notification payload. Clicking follows validated app routes and never auto-answers calls. Device Focus, mute and notification settings control sound/banner delivery; the website cannot force priority above them.

Automated Verified: 256 regression checks plus JS/inline syntax/diff. Actual PostgreSQL tests cover ownership, secret/RPC denial, invalid endpoints, stable retries, preference/block/read suppression, leasing, session deletion and safe rollback. Worker tests use real VAPID/ECDH encryption; unauthorized and expired providers, generic payloads, safe worker navigation, permission gestures, iPhone tab gating, account switching and failed device registration covered. Production Edge unauthenticated config/dispatch requests return 401; RPC grants, triggers, Vault signature and active cron checked. No actual customer subscriptions/events created.

User Verified: support submissions and followed-post IN-APP notification delivery accepted. Not Verified: real subscribed-device push, iPhone Home Screen installation/permission, physical sound/banner appearance, server VAPID lazy initialization on a real session, provider delivery latency and real logout behavior. No mobile browser or actual provider delivery is claimed tested.

Deployment: managed Supabase migration version 20261012005350 was assigned by MCP and copied verbatim into the migration directory. Prior CLI telemetry was rejected; CLI was not retried or bypassed. database/web-push.sql is the matching source; rollback-web-push.sql disables registration/queue hooks/cron while retaining history, ownership and Vault material.

Advisors: preexisting findings remain. New private push_config/push_jobs have RLS with no client policies deliberately (default deny, no raw client grants), so their [no-policy information](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) is expected. New indexes not yet used are retained for FK/queue access ([guidance](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)). pg_net registered in public adds [extension-location warning](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public); objects live in the separate net schema, which is not exposed through Data API. Client network RPC access is not added; wake/config/dispatch APIs are restricted. Schema USAGE on net remains Supabase-managed; attempted revoke in source does not remove platform-owned grants. REST Accept-Profile net probe is denied (406). [Supabase pg_net permissions/troubleshooting](https://supabase.com/docs/guides/database/extensions/pg_net).

Automatic approval review rejected dropping/recreating pg_net to relocate it, stating the move could break the existing wake_push reference and disrupt delivery. No retry/indirect bypass. The current non-exposed schema is retained, and functional deployment continues. Any later relocation needs separate review/authorization; it is not required for this push path.

Incomplete: unsupported push-service hosts, browser subscription-change automation, end-to-end phone acceptance and high-volume fan-out monitoring. Multiple devices supported; background delivery requires provider/OS cooperation and active signed-in session.

Sources: [Apple Web Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [WebKit Home Screen requirements](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Supabase scheduling](https://supabase.com/docs/guides/functions/schedule-functions), [web-push source](https://github.com/web-push-libs/web-push).

Delivery failure isolation: managed migration 20261012010405 locks subscription references during enqueue and catches optional wake/network failures, preserving ordinary notification/message/post saves. Mocked unavailable net.http_post test confirms in-app history survives; retry queue remains available. This strengthens core-flow protection without changing notification permissions.
