# Plaza social card revision

Implemented: avatar/name/Host badge/derived age/region/stored last-seen information; compact SVG heart/comment/repost/share/save row matching the owner's reference direction, post options menu and a gift icon on media or text-only cards. Missing profile data is shown as unavailable; stored presence is not independently verified live presence. Existing profile and image URLs are safely rendered. Native dialog sheets support options, report, share and gifts. Discover/Saved/Reposts filters and per-post share deep links added.

Persistent bookmarks are private to the owner. Repost state/counts refer to saved Mimo repost marks and the owner's Reposts filter, not a newly authored post or external social publishing. Original Host-only publishing remains. Either-direction blocks still apply. No fake share counts are displayed. Options support blocking the author, reporting a post and deleting an own post.

Report: category, mandatory reason, optional max-three JPEG/PNG/WebP images (raw max10 MB each, resized longest edge1600 and JPEG-compressed, max3 MB stored each). Dedicated plaza_reports holds text snapshot, original post UUID and author UUID; deleting the post nulls only its FK and preserves the report. Reporter/admin can read; normal users cannot change status, delete reports or access others' evidence. Private Storage bucket policies permit own-folder uploads/read and cleanup of unreferenced files; registered evidence cannot be removed by reporter. RPC checks existing evidence path ownership and matching report UUID. Retries reuse the report UUID and completed upload paths, changed payload uses a new UUID. Browser compression and actual Storage HTTP upload are NOT device-verified. Abandoned/failed uploads can leave private orphan files: automated retention/quota cleanup remains incomplete.

Share: Facebook/Telegram/X/WhatsApp link-composer targets, native device sharing and Copy link fallback. Instagram/TikTok buttons copy the link; native destinations depend on device/browser/apps. No direct IG/TikTok publishing API, no automatic post sending, no completed external-sharing claim. Recipients must sign in and retain block restrictions. Official references consulted: Telegram Sharing Button, MDN Navigator.share, Meta Share Button, X publish/web intents.

Gift panel reads existing active gift catalog and exact diamond-price strings, supports selection and permanently disables Send. Five active production gifts existed before this task; no gifts/prices were seeded/changed. Financial sending, deductions, Host revenue/split and payout remain incomplete pending approved settlement rules. This UI must not imply a completed gift transfer.

Verified: 139 isolated PostgreSQL/JSDOM/media checks, syntax/whitespace. New checks cover own bookmark/repost, blocked state, report evidence ownership/status/snapshot retention, dialog retry/session cleanup, profile/icon rendering, gift-disabled behavior and mocked upload compression/retry/session cancellation. Production migration/bucket private status/3 MB MIME restrictions/three Storage policies/RLS/functions/grants and no-UID empty reads confirmed. Advisors unchanged; inherited remediation links remain in NOTIFICATION_CENTER_REVIEW.md. No real posts, reports, files or money were created/changed for verification.

Not Verified: real Storage network upload and image decoding/compression, production transactional report/mark operations/concurrency, phone/desktop visual acceptance, external app share completion and current last-seen accuracy. No production admin exists; moderation queue/UI/review/audit operations, upload quotas/retention, dynamic photo publishing and full gift settlement remain incomplete.
