# Plaza text feed checkpoint

Implemented: existing Home/Me → Plaza now opens plaza.html. Signed-in members browse paginated newest-first updates; only the actual Host profile role exposes the composer and can publish text (1–2000 characters). User/Host can like/unlike with an explicit desired state, comment (1–1000), and delete their own content after confirmation. Deleting an own post cascades its likes/comments through inherited foreign keys. Feed shows viewer-visible counts as exact strings and own like state; comments are newest-first with pagination. Existing valid HTTPS post images can display (max six); new image publishing/upload is not enabled. Profile names/content use text rendering and profile links require UUIDs. Visible polling, login/error/empty feedback, logout/account cleanup, draft retention and retry UUIDs included. No seed posts or roles were created.

Database: retained inherited Host/ownership policies, added six restrictive policies. Either-direction blocks hide the other author's posts and deny new likes/comments; blocked commenters are excluded from others' comment lists. Own raw like/comment records remain readable for self-removal. RPC comment lists still require a currently visible parent post. Counts reflect viewer-visible rows and need not equal another viewer's counts. Existing contact helper is reused; no new privileged public function. All six new APIs are SECURITY INVOKER, empty search_path, anonymous EXECUTE denied. Trigger guards protect actor/identity/timestamps/content length, keep existing media immutable on updates and enforce Host role. Raw client TRUNCATE/REFERENCES/TRIGGER revoked. Post/comment UUID replay is idempotent only for unchanged content/ownership; unlike uses explicit false instead of blind toggle. Bounded SQL pagination indexes added.

Verified: all 131 automatic checks (12 new PGlite/JSDOM checks) pass, plus JavaScript/inline syntax and whitespace. Production migration applied; policies/triggers/grants/functions verified, anon read/execute denied, no-UID feed empty and role null. Advisors retain the inherited warnings and remediation links documented in NOTIFICATION_CENTER_REVIEW.md; no new warnings. No real content was inserted/deleted for verification.

Not Verified: real signed-in production publish/like/comment/delete, callback/concurrent block behavior, two-account block acceptance, phone layout/media and actual browser visual acceptance. Isolated PGlite/JSDOM tests do not prove production concurrency or mobile rendering. Incomplete: image upload/storage policies, edit UI, spam quotas, reporting/moderation workflow, admin removal/audit, automated review, and activity notifications/browser push. This is a functioning text-feed implementation, not a complete production moderation system.

Device checklist: Host publishes; User sees it without a composer, likes/unlikes, comments and deletes own comment; another Host cannot alter/delete the post; author deletes own post; either participant blocks and confirms feed/interaction restriction; logout clears feed/drafts. No need to retest accepted Beauty/call media for this release.

Rollback: revert frontend and apply database/rollback-plaza.sql to disable new APIs. Retain content, RLS/identity guards and safe grants rather than restoring destructive privileges. Migration file was prepared directly in the existing safer repository/MCP workflow after the earlier CLI telemetry rejection; telemetry was not retried.
