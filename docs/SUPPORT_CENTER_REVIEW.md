# Help and support center

Implemented: Settings → Help & Customer Service now opens support.html. Signed-in User/Host can submit a categorized request, view their own paginated tickets/history, append text replies to open/in-progress tickets, and close their request. First ticket/message creation is atomic. Reusing an unchanged request UUID retries without duplication; changed content rejects. Existing admin accounts may view all tickets in Support queue, reply, manage priority, start/resume review, resolve and close. Closed tickets cannot reopen. Resolved tickets do not accept replies until an admin resumes review. No attachments or guaranteed response time. Visible polling refreshes every 30 seconds. Safe text rendering, session cleanup, login/retry/empty feedback and retained draft on failure included. Settings → Wallet now opens the implemented wallet instead of its old placeholder.

Authorization: existing ownership/admin RLS retained. New invoker trigger guards prevent ordinary users changing lifecycle/priority/identity, forging support senders or timestamps, or replying to terminal tickets. Replies are append-only; client delete/TRUNCATE/trigger/reference grants removed. RPCs are SECURITY INVOKER with empty search_path, signed-in Auth checks and anonymous EXECUTE denied. Ticket lock serializes reply against closure; status updates include the expected status to reject stale actions. No admin accounts/roles assigned and no customer records rewritten. Production currently has zero admin profiles; an owner-designated account is required before someone can answer through the queue. Never pick an account or elevate someone based on a generic continue message.

Verified: 119 automated checks (12 new isolated PostgreSQL/JSDOM checks); JavaScript/inline syntax and whitespace. Production migration applied; functions/triggers/grants confirmed and real no-Auth-context read returned zero tickets/messages with no admin access. Security advisors unchanged: inherited findings/remediation URLs are recorded in NOTIFICATION_CENTER_REVIEW.md. No new public privileged functions.

Not Verified: production transactional create/reply/concurrent-close behavior, actual admin operation on production, mobile UI and two-account acceptance. PGlite/JSDOM checks are isolated tests, not a phone/browser acceptance. No synthetic production users or tickets were created for verification. Support does not send email/push or generate in-app reply notifications in this release. Reports here are support-category submissions, not automatic moderation actions. Spam quotas, attachments, admin assignment/audit dashboard, response-time operations and official-message publishing remain incomplete.

Device checklist: submit a request, retry after network failure, view its saved first message, append a reply, close it; ensure replies stop and another account cannot see it. Once the owner designates an admin, verify queue visibility/reply/priority/status and regular user isolation.
